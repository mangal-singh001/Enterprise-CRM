# 🚀 Internal Enterprise CRM Platform - Comprehensive Overview & Execution Guide

---

## 📋 1. Project Description

### Executive Overview & Business Objective
Our company operates multiple SaaS products managed by separate internal operations teams. Previously, each product had its own disjointed internal tools, leading to duplicated engineering effort, fragmented user experiences, and high maintenance costs.

The **Internal Enterprise CRM Platform** solves this by providing a single, unified enterprise web application that serves multiple internal SaaS products while remaining modular and extensible for future products, entities, and user roles with minimal engineering effort.

---

### 🏛️ Architectural Highlights & Key Features

1. **Identity Provider (IdP) SSO Authentication (No Login Page)**:
   - Employees navigate to the application with a signed SSO authentication token generated by internal systems: `http://localhost:3000/?token=<signed_token>`.
   - The frontend `AuthContext` intercepts the token, validates the signature via `/api/v1/auth/verify-token`, extracts employee identity (`email`, `name`, `products`, `role`), issues a secure session JWT, and cleans up the URL parameter.

2. **Extensible Dynamic Entity Registry Architecture**:
   - Rather than hardcoding custom tables and forms for every new entity, entities register their schema, validation rules, display columns, and dynamic form fields once in `backend/app/core/registry.py`.
   - The React frontend queries `/api/v1/metadata/entities/{productId}/{entityId}` to render tables, status badges, sort controls, and channel-dependent dynamic input forms out of the box.
   - **Low-Code Growth**: Adding a new SaaS product or entity requires only an ORM model and a registration entry in Python.

3. **Multi-Product SaaS Workspaces**:
   - **EduPulse Workspace**:
     - **Subscription Plans**: Manage plan names, pricing, billing cycles (Monthly, Quarterly, Yearly), and structured JSON feature configs.
     - **Message Templates**: Manage transactional notifications across Email, SMS, WhatsApp, and Push channels with channel-dependent input schemas (Email subject & HTML body vs SMS message text & sender ID).
   - **CloudMetric Workspace**:
     - **Client Sites**: Domain white-lists, live API key management with an auto-generator tool, status controls (Active, Suspended, Maintenance), and daily request quotas.
   - **Executive Dashboard**:
     - Cross-product executive metrics, quota bandwidth monitors, quick product workspace switchers, and a real-time system governance audit feed tracking every `CREATE`, `UPDATE`, and `DELETE` operation.

4. **Product-Level RBAC & Security**:
   - Enforces strict product isolation (e.g. an operations employee authorized only for `EduPulse` cannot view or mutate `CloudMetric` records).

## ⚙️ 2. How to Execute & Run the Project

### Step 1: Start the Backend Server (FastAPI)

> [!NOTE]
> The backend automatically creates and seeds sample initial data for EduPulse and CloudMetric upon first startup!

Open a terminal window and run:

```bash
# 1. Navigate to the backend directory
cd C:\Users\kisha\.gemini\antigravity-ide\scratch\enterprise-crm\backend

# 2. Install backend dependencies (if not already installed)
C:\Users\kisha\AppData\Local\Programs\Python\Python312\python.exe -m pip install -r requirements.txt

# 3. Start the FastAPI backend server on port 8000
C:\Users\kisha\AppData\Local\Programs\Python\Python312\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

- **Backend API Base URL**: `http://127.0.0.1:8000`
- **Interactive OpenAPI (Swagger) Documentation**: `http://127.0.0.1:8000/docs`
